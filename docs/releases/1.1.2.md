# BalanceEQ 1.1.2 candidate

Build 6, not yet published as a GitHub release. Public 1.1.1 remains unchanged.

- **Check for Updates…** is available from the menu-bar menu, application menu
  and About window. The native Sparkle dialog offers download, installation and
  relaunch without a Terminal command.
- Sparkle 2.10.1 is pinned and bundled. Both the feed and update archive require
  an Ed25519 signature matching the embedded public key; archive verification
  happens before extraction. Invalid feed signatures never expire into trust.
- Checks and installs are manual, with no system profiling or background polls.
  Updates preserve presets, stop audio during restart and leave EQ stopped after
  relaunch. Existing 1.1.1 installations need one initial manual update to gain
  this feature. The audio callback and buffers are unchanged.

This remains an ad-hoc-signed, unnotarized community build. Update signatures
do not replace Apple notarization; Gatekeeper and capture permission can still
require user action. Intel/macOS 14.2, clean-Mac and other outstanding hardware
acceptance remain unverified.

## Verification on 10 November 2026

- All 27 existing Swift tests, app self-checks, C callback checks and installer
  checks passed. Universal arm64/x86_64 build and nested signature verification
  passed. Updater configuration/packaging checks run in the regular scripts.
- Actual UI: a test host discovered the signed 1.1.2 fixture, rejected a
  one-byte-tampered archive before installation, then successfully downloaded,
  replaced itself and relaunched with the valid archive. The temporary fixture
  was served only over loopback. The final app has the production HTTPS feed
  and no test transport exceptions.
- The current preset file matched the pre-test snapshot. The installed app
  checked the live signed feed and reported up to date. FiiO K11 processing was
  restored at 48 kHz/128-frame I/O; this is not an end-to-end latency measurement.

The initial signed feed is live on the dedicated `updates` branch, with no
release items until the first updater-enabled release is published. Follow
[the update publication instructions](../UPDATES.md) for every future release.
